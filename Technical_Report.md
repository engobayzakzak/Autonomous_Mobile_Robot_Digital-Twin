## 1. System Kinematics & Physical Modeling

### 1.1 Non-Holonomic Differential Drive Dynamics
The AMR chassis is modeled as a non-holonomic mobile platform operating on a planar surface $\mathbb{R}^2$. The generalized state vector is defined as:

$$\mathbf{q} = \begin{bmatrix} x & y & \theta \end{bmatrix}^T$$

where $(x, y)$ represents Cartesian position coordinates in the global map frame, and $\theta$ denotes the robot orientation angle.

```text
                       y ▲
                         │       / Left Wheel (w/2)
                         │     ┌───┐
                         │     │   │
                         │     └───┘
                         │       │   
                         ├───────┼────────► x (Heading)
                         │       │  r
                         │     ┌───┐
                         │     │   │
                         │     └───┘
                         │       \ Right Wheel (-w/2)
```


The non-holonomic constraints prevent lateral movement (zero side-slip along the wheel axle axis):
$$\dot{x} \sin\theta - \dot{y} \cos\theta = 0$$
The forward differential kinematics equation mapping left and right wheel angular velocities $(\omega_L, \omega_R)$ to robot linear velocity $v$ and angular velocity $\omega$ is given by:
```text
┌───┐   ┌                  ┐ ┌────┐
│ v │   │  r/2        r/2  │ │ ωR │
│   │ = │                  │ │    │
│ ω │   │  r/W       -r/W  │ │ ωL │
└───┘   └                  ┘ └────┘
```
where $r = 0.05\text{ m}$ is the wheel radius and $W = 0.35\text{ m}$ is the track width (wheel separation).



2. Sensor Integration & ROS-Gazebo Transport Bridge
The digital twin includes simulated physics sensor models integrated via Gazebo plugins and mapped to ROS 2 topics through ros_gz_bridge:
1- 2D Planar LiDAR (/scan): 360-degree horizontal ray sweep @ $10\text{ Hz}$, $0.15\text{ m} - 12.0\text{ m}$ range, publishing sensor_msgs/msg/LaserScan.
2- RGB Visual Camera (/camera/image_raw): $640 \times 480$ resolution @ $30\text{ FPS}$, publishing sensor_msgs/msg/Image.
3- Simulation Clock (/clock): Monotonic simulation clock bridging gz.msgs.Clock $\rightarrow$ rosgraph_msgs/msg/Clock to guarantee global $TF2$ transform synchronization across Nav2 lifecycle nodes.



3. Pose-Graph Simultaneous Localization and Mapping (SLAM)

3.1 Pose-Graph Optimization Formulation
slam_toolbox executes non-linear pose-graph SLAM. Nodes in the graph represent historical robot poses $\mathbf{x}_i$, and edges represent relative spatial constraints $\mathbf{z}_{ij}$ generated by scan matching between LiDAR frames $i$ and $j$:
$$\mathbf{x}^* = \arg\min_{\mathbf{x}} \sum_{ij} \mathbf{e}(\mathbf{x}_i, \mathbf{x}_j, \mathbf{z}_{ij})^T \mathbf{\Omega}_{ij} \mathbf{e}(\mathbf{x}_i, \mathbf{x}_j, \mathbf{z}_{ij})$$
where $\mathbf{e}(\cdot)$ is the non-linear residual error function and $\mathbf{\Omega}_{ij}$ is the information matrix (inverse covariance) of the measurement. Optimization is solved using sparse Cholesky matrix decomposition.



4. Probabilistic Navigation & Path Planning (Nav2)

4.1 AMCL Particle Filtering
Adaptive Monte Carlo Localization estimates the robot's belief distribution $\text{Bel}(\mathbf{x}_t)$ over the map frame using a set of $M$ weighted particles $S_t = \{(\mathbf{x}_t^{[m]}, w_t^{[m]})\}_{m=1}^M$:
1- Motion Model Prediction:
$$\mathbf{x}_t^{[m]} \sim p(\mathbf{x}_t \mid \mathbf{u}_t, \mathbf{x}_{t-1}^{[m]})$$
2- Sensor Measurement Update:
$$w_t^{[m]} = P(\mathbf{z}_t \mid \mathbf{x}_t^{[m]}, m_{\text{map}})$$
3- Importance Resampling: Particles are resampled in proportion to weights $w_t^{[m]}$, condensing the particle cloud around the true state estimate.

4.2 Costmap Inflation & Local Controller
- Global Costmap: Evaluates static occupancy grid layers with inflation potential fields:
$$\text{Cost}(r) = \exp\left(-\alpha \cdot (r - r_{\text{robot}})\right) \cdot \text{Cost}_{\text{max}}$$
Path planning is solved globally via $A^*$ graph search.
- Local Controller (DWB): Evaluates forward motion trajectory samples over velocity space $(v, \omega)$ within time horizon $T = 1.7\text{ s}$, picking trajectories that minimize distance to path while maintaining safe obstacle clearances.



5. Vision Perception & Visual Servoing
The amr_perception package executes an OpenCV pipeline:
1- Subscribes to /camera/image_raw (sensor_msgs/msg/Image).
2- Transforms BGR frame into HSV color space for illumination-invariant thresholding ($H \in [0, 10] \cup [170, 180]$).
3- Calculates contour bounding boxes, computes centroid normalized horizontal error $\delta_x \in [-1.0, 1.0]$, and estimates target spatial coordinates.
4- Publishes annotated image stream to /camera/image_detected and projects 3D spatial markers to /visualization_marker.
